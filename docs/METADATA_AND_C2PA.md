# メタデータとC2PAの表示仕様

## 「すべて」の定義

対応解析器が取得できる項目を、重複を含めて欠落させず表示することを目標とする。あらゆる独自形式・未知タグの意味を解釈できる保証はしない。未対応、解析失敗、部分解析、上限による省略を明示し、空の一覧だけで「情報なし」と結論づけない。

## 情報の種類

| 種別 | 例 |
| --- | --- |
| OS由来 | ファイル名、サイズ、取得可能なファイルシステム日時 |
| 埋め込み情報 | EXIF、GPS、IPTC、XMP、ICC、対応するMakerNotes |
| メディア構造 | 画像寸法、色空間、動画コンテナー、各トラック、コーデック、時間 |
| C2PA | マニフェスト、assertion、署名、検証結果 |
| 未知の情報 | 取得可能な識別子・位置・長さ・バイナリ |
| 計算値 | 解析器が算出した値。埋め込み値とは明確に区別する |

情報の出所を区別し、同名項目を名前だけで統合しない。動画ではトラック番号、配列では要素番号、構造体では階層をキーパスに残す。

## 内部モデルと表示

単純な `Map<String, String>` は使わず、型と重複を保持する項目リストを用いる。設計上必要な項目は以下とする。具体的なDart型は試作時に確定する。

```text
MetadataEntry
  id              セッション内の一意識別子
  namespace       名前空間・グループ
  path            所属・配列・トラックを含むパス
  occurrence      同一パスの出現番号
  valueType       文字列、数値、配列、構造体、バイナリなど
  rawValue        解析器が返した型付き値または遅延取得参照
  displayValue    人が読む表示値
  origin          OS由来、埋め込み、計算値、検証結果など
  extractor       解析器とそのバージョン
```

解析器が返す生の値と表示値を分け、丸めや単位変換で情報を失わない。rawValueは必ずしも元ファイル上のバイト列ではない。バイト列や位置が取得できる場合は別の詳細として扱い、取得できない場合は推測しない。

一覧はキー・値の2列を基本とし、検索、キー／値のコピー、長い値の全文表示を提供する。巨大なバイナリはサイズと取得状態を示し、必要時に読む。表示を省略しても元データが存在しないようには見せない。

## C2PAの検証軸

| 観点 | 状態例 |
| --- | --- |
| 存在 | あり、未検出、判定不能 |
| 解析 | 成功、未対応、破損 |
| 内容の整合性 | 一致、不一致、未検証 |
| 署名 | 有効、無効、検証不能 |
| 信頼 | 設定した基準を満たす、満たさない、不明 |
| 外部参照 | なし、未取得、取得済み、取得失敗 |

署名の検証成功は撮影内容の真実性を保証しない。C2PA未検出も改ざんの証拠として扱わない。未対応形式や解析エラーを「C2PAなし」に変換しない。

署名者、履歴、マニフェストやassertionの詳細、検証エラーと根拠を確認できるようにする。複数のマニフェストやingredientがある場合は関係を保持し、要約の対象を明示する。検証日時、検証ライブラリのバージョン、使用した信頼リストの識別情報、オンライン確認の有無を記録する。信頼リストの供給元・更新方式は採用前の判断項目とし、未設定時に「信頼済み」と表示しない。

## ネットワークとプライバシー

既定ではローカル解析のみとする。外部マニフェストや証明書関連情報の取得が必要なら、接続先と目的を表示し、ユーザー操作で取得する。ファイルを自動アップロードしない。

ファイル内URLは信頼できる命令として扱わない。許可するスキーム、リダイレクトと最終接続先、ローカルネットワークへのアクセス、サイズ、時間、再帰的取得を制限する。拒否・取得失敗・未取得を区別する。位置情報や証明書情報などを通常ログへ無制限に出力しない。

## 形式対応の記録

JPEG、PNG、HEIC、TIFF、WebP、MP4、MOVを初期検証候補とする。各形式について「プレビュー」「メタデータ」「C2PA」を独立して記録する。コンテナーを開けてもコーデックを再生できるとは限らないため、動画のコーデックも記録する。これらは検証候補であり、初版での対応を確約する一覧ではない。
