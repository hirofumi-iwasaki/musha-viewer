# 設定保存とプラットフォーム対応

実装状況（0.1.0）：ウィンドウの通常サイズ・位置・最大化状態、インスペクターの幅と表示、テーマをバージョン1のJSONへ保存します。macOSではApplication Support、LinuxではXDG設定ディレクトリー、WindowsではLocalAppDataを使用します。破損または未対応バージョンは保持し、そのセッションでは上書きしません。保存は遅延して直列化し、終了時に完了を待ちます。履歴は保存しません。macOSでの復元とSandbox動作は実機未検証です。以下には今後の方針も含まれます。

## 設定形式

ユーザーが確認しやすいバージョン付きJSONを採用する。現在のバージョン1形式の例：

```json
{
  "schemaVersion": 1,
  "window": {
    "width": 1280,
    "height": 820,
    "x": null,
    "y": null,
    "maximized": false
  },
  "inspector": {
    "visible": true,
    "width": 340
  },
  "theme": "system"
}
```

幅・高さはFlutterの論理ピクセルで扱う。デスクトップでは復元用の通常状態の位置・サイズを保存し、最大化中のサイズで上書きしない。位置は取得できる場合に保存する。画面構成が変わったら可視領域へ補正し、ウィンドウが画面外へ消えないようにする。モバイルではウィンドウ位置・サイズを適用しない。

## 保存先

| OS | 方針 |
| --- | --- |
| macOS | OS APIで得るApplication Supportのアプリ専用領域。Sandbox版はコンテナー内 |
| Windows | OS APIで得るLocalAppDataのアプリ専用領域 |
| Ubuntu | `$XDG_CONFIG_HOME/musha-viewer`。未設定時は `~/.config/musha-viewer` |
| iOS / iPadOS | アプリコンテナー内のApplication Support |
| Android | アプリ専用の内部ストレージ |

保存ファイル名は `settings.json` とする。組織名・Bundle IDに依存する最終パスは識別子を決定した時点で記録し、OSのホームパスを決め打ちしない。クロスプラットフォームパッケージの既定値がこの方針と一致するか確認する。

キャッシュは設定とは別のOS推奨キャッシュ領域へ置き、削除しても設定を失わないようにする。機密情報を設定JSONへ保存しない。

## 保存と復元

- リサイズやペイン幅変更はまとめて保存し、終了時に保留中の保存を完了する。
- 同じディレクトリの一時ファイルへ書き込み、OSに適した置換で保存する。
- 欠落項目は既定値で補い、破損時は元ファイルを保持して既定値で起動する。未知の新しいスキーマを不用意に上書きしない。
- 履歴の保存は設定で選べるようにし、初期状態は無効とする。履歴を有効にするまで、最近開いたファイルを永続化しない。
- 初期状態はシステムテーマ、インスペクター表示とする。C2PAの外部情報取得はオフライン固定であり、設定項目はない。上記のサイズは画面に収まる場合の初期値とする。

## macOSとApp Store

初期試作からApp Sandboxを有効にする。ファイル選択、ドラッグ＆ドロップ、Finder経由の入力ごとに読取アクセスを確認する。security-scoped URLの開始・終了を、プレビューと解析の寿命に合わせて管理する。

再起動後もアクセスを保持する機能を実装する場合はsecurity-scoped bookmarkを使用し、失効した参照は再選択を求める。履歴にパスを記録しただけで権限が復元すると仮定しない。

Bundle IDは所有するドメインまたは公開主体を確認して確定する。署名鍵・証明書・個人認証情報はリポジトリに入れない。ストア向け署名・申請、GitHub配布向け署名・公証、Releaseビルドの動作はそれぞれ確認する。

## 将来の移植

共通UIとDartモデルを維持し、動画再生、ファイル参照、ウィンドウ管理をOS別アダプターで実装する。iOS/iPadOSのドキュメントプロバイダー、AndroidのStorage Access Framework、Linuxのサンドボックス化された配布方式ではアクセス方法が異なるため、一般的なローカルパスを前提にしない。

移植時には最低OS、CPU、画像形式、動画コーデック、C2PA、アクセシビリティ、配布方式を実機検証し、実際に確認した環境を記録する。
