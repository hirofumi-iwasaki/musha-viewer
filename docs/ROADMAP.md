# 開発順序と受け入れ条件

0.1.0では画像プレビュー、簡易メタデータ、C2PA検証、設定保存、ドラッグ＆ドロップを対象とする。動画とFinderからの関連付け起動は後続へ延期する。以下の計画そのものは試験実績ではなく、実績は[実装記録](IMPLEMENTATION_0_1_0.md)に分けて記録する。

## 段階1：配布可能性を確認する技術試作

- Flutter安定版、Dart、Xcode、Rustの組み合わせを選び、バージョンを記録する。
- macOS 27でSandboxを有効にしたReleaseビルドを作り、開発ツールから独立した起動を確認する。
- ファイル選択、画像表示、動画再生、RustとのFFI連携を確認する。
- 対応CPUを実際のビルド・実行結果から決める。署名・公証・ストア配布の制約を整理する。

出口条件：対象環境で実行でき、ファイルの読取権限と各アダプターの成立性が確認できること。

## 段階2：解析器とC2PA検証の評価

JPEG、PNG、HEIC、TIFF、WebP、MP4、MOVを候補に、独立した比較ツールと抽出結果を照合する。EXIF、XMP、IPTC、ICC、MakerNotes、重複項目、複数トラック、未知タグの取得範囲を記録する。

c2pa-rsなどの候補を使い、正常な署名、内容不一致、無効署名、信頼不明、未検出、未対応、破損、外部参照未取得を区別できることを確認する。依存関係のライセンスと再配布条件をレビューし、採用結果を記録する。

出口条件：初版の形式別対応表、採用バージョン、既知の欠落、信頼方針が明確であること。テスト用ファイルは配布許諾を確認し、個人情報を含む私有ファイルを無断で公開しない。

## 段階3：縦に通した閲覧アプリ

ファイルを開いて、プレビュー、2列のメタデータ一覧、C2PA結果、設定復元までを実装する。UIに解析状態と部分失敗を反映し、キャンセルと古い結果の破棄を行う。

出口条件：macOS 27のSandbox内で1ファイルを開き、3つの機能が独立して結果を表示できること。

## 段階4：0.1.0の公開準備

README、対応形式表、既知の制約、第三者ライセンス、ビルド手順、CONTRIBUTING、SECURITYを整備する。Flutter/Dartの解析・試験と、採用したネイティブコードの試験・ビルドをCIへ追加する。アプリが存在する前に、動くように見える仮のビルドCIは追加しない。

## 受け入れ試験

| 観点 | シナリオと期待結果 |
| --- | --- |
| 元ファイル保護 | 開く前後のハッシュが一致する。再生・解析・終了で元のバイトを書き換えない |
| 入力経路 | ファイル選択、ドラッグ＆ドロップ、Finder経由で権限を取得できる |
| 部分失敗 | プレビュー不可でも抽出結果を表示し、C2PA失敗でもプレビューを継続する |
| ファイル切り替え | 高速に切り替えても前のファイルの結果が混入しない |
| メタデータ | 同名キー、配列、複数トラック、長い値、バイナリ、未知タグを区別できる |
| 大量・破損データ | 巨大・破損・切り詰めファイルでUIを停止させず、制限・失敗を示す |
| C2PA | 整合性、署名、信頼、未検証理由を混同せず表示する |
| 外部参照 | 初期状態で自動接続せず、手動取得・拒否・失敗を区別する |
| 設定 | 再起動で復元し、破損設定と画面構成変更でも起動・操作できる |
| アクセシビリティ | キーボード、VoiceOver、文字サイズ変更で主要操作と結果確認ができる |
| 配布 | 開発ツールなしでReleaseアプリが起動し、権限・再生・解析が機能する |

試験結果はOS・CPU・SDK・依存バージョンとともに記録する。ビルド成功だけで実機動作を確認済みとしない。

## 後続の展開

macOS初版を基準に、WindowsとUbuntuのデスクトップ対応、iOS/iPadOSとAndroidのファイルアクセス・画面適応を進める。OSごとに形式・コーデック・C2PA・配布方式を確認する。移植の順序とリリース時期はmacOS試作の結果を踏まえて決定する。
