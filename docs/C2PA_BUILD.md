# C2PA native verifier

The app embeds a locally patched, vendored c2pa-rs 0.91.10 (MIT OR Apache-2.0), pinned together with its transitive dependencies in `native/c2pa/Cargo.lock`. A Rust toolchain of at least 1.96, Cargo, a C toolchain and the platform SDK are required. The Rust targets `aarch64-apple-darwin` and/or `x86_64-apple-darwin` must be installed for the Xcode architectures being built. Set `CARGO` to the Cargo executable if it is not on PATH. Builds use `--locked`; dependency downloads require access to crates.io. No credentials or prebuilt native binaries belong in the repository.

Linux Flutter builds invoke `scripts/build-c2pa.sh` from CMake and place `libmusha_c2pa.so` in the application's `lib` directory. macOS Xcode builds invoke the same script for each `ARCHS` architecture, combine them with `lipo`, copy the dylib into `Contents/Frameworks`, and sign it using the active build identity when signing is enabled. Xcode and an SDK supporting the configured macOS 27 deployment target are required; a Linux build cannot validate that packaging or signature.

Run `cargo test --locked --manifest-path native/c2pa/Cargo.toml` to check the native adapter and `flutter build linux` to build the application bundle. The native script can also be invoked independently. The C ABI in `native/c2pa/include/musha_c2pa.h` takes bytes and a MIME type and returns owned UTF-8 JSON; release it once with `musha_c2pa_free`. Call it on a background isolate. The caller must supply valid pointers throughout the call; the API copies neither input nor output across an FFI boundary automatically.

Offline verification is the default; online verification requires an explicit request. A user reported a successful online check of one Leica M11-D DNG on a physical Mac on 2026-11-04; this does not guarantee general compatibility. The SDK may fetch remote manifests, CAWG identity resources and OCSP responses using bounded HTTPS GET requests. Plain HTTP is allowed only for a strict canonical OCSP GET to the exact host `ocsp.leica.systems`; other HTTP resources and OCSP endpoints are rejected. Private addresses and redirects are blocked, and proxies are unsupported. The budget is 20 seconds including DNS and at most 16 requests, with at most 16 MiB per response and 1 MiB for an HTTP OCSP response. Original image bytes are never uploaded. Requests disclose the client IP address and requested URLs or certificate identifiers to the contacted servers; a Leica OCSP request discloses the client IP and certificate identifiers to Leica. Because the request uses unencrypted HTTP, network intermediaries can also observe its certificate identifiers.

A locally patched, vendored c2pa-rs 0.91.10 validates the live response signature, CertID and EKU, requires the responder to be directly authorized by the actual signer certificate issuer, chains the responder to the bundled official Leica C2PA root, and requires a currently fresh response. It emits `org.musha.liveOcsp.good` or `org.musha.liveOcsp.revoked` as an informational marker for a definitive live Leica revocation result. Online completion requires a definitive live leaf OCSP result and a Good result for every required non-root issuer check. Missing AIA, a failed or unknown issuer response, or a truncated chain leaves the check incomplete even if the leaf is Good. A result without a marker does not confirm live Leica revocation status. Successful requests cover only resources attempted. No general C2PA trust list is configured: `verify_trust=false`, and the bundled Leica root is used only to authorize the Leica OCSP responder chain. Overall trust remains unknown, even after a successful live check.

既定はオフライン検証で、オンライン検証は明示的に要求した場合のみ行います。2026-11-04 にユーザーの Leica M11-D DNG 1件について Mac 実機でオンライン検証が成功したとの報告がありましたが、一般的な互換性を保証するものではありません。SDK は外部マニフェスト、CAWG 識別情報、OCSP 応答を上限付き HTTPS GET で取得する場合があります。平文 HTTP は正確なホスト `ocsp.leica.systems` への厳密な正規形式の OCSP GET に限り許可し、その他の HTTP リソースや OCSP エンドポイントは拒否します。プライベートアドレスとリダイレクトは遮断し、プロキシには対応しません。上限は DNS を含め合計20秒、最大16要求、応答ごとに16 MiB、HTTP OCSP 応答は1 MiBです。元画像のバイト列はアップロードしません。要求により接続先にクライアント IP アドレス、要求 URL や証明書の識別子が伝わります。Leica への OCSP 要求では、IP アドレスと証明書の識別子が Leica に伝わります。要求は暗号化されていない HTTP のため、ネットワークの中継者も証明書の識別子を見ることができます。

ローカルで修正し同梱した c2pa-rs 0.91.10 は、ライブ応答の署名、CertID、EKU を検証し、応答者が実際の署名者証明書の発行者に直接認可され、同梱の Leica 公式 C2PA ルートへ連鎖し、応答が現在有効な期間内であることを要求します。確定した Leica のライブ失効結果には、情報マーカー `org.musha.liveOcsp.good` または `org.musha.liveOcsp.revoked` が出力されます。オンライン確認の完了には、リーフ証明書の確定したライブ OCSP 結果と、必要なすべての非ルート発行者の確認結果が Good であることが必要です。AIA がない場合、発行者の応答が失敗または不明な場合、チェーンが途中で切れている場合は、リーフが Good でも確認は不完全です。マーカーがない場合、Leica のライブ失効状態は確認できません。要求の成功は試行したリソースに限られます。一般の C2PA 信頼リストは設定されず、`verify_trust=false` で、同梱 Leica ルートは Leica OCSP 応答者チェーンの認可にのみ使います。ライブ確認が成功しても全体の信頼状態は不明です。

No general C2PA trust list is configured; `trust` remains `unknown`, even if the SDK reports a cryptographically valid signature. The SDK's full manifest and validation result codes are retained. The summary reports a positive signature or hard binding only when the corresponding SDK success code exists; missing evidence remains unknown. Ingredient validation is in the raw SDK report. A successful signature says nothing about whether the depicted event is true. This version accepts an in-memory buffer and has no in-flight cancellation; the caller must apply its own size limits.

The direct SDK is dual-licensed under MIT OR Apache-2.0. The native library also statically incorporates Cargo dependencies under their respective licenses; distribution requires an inventory and inclusion of the applicable license texts and notices for the exact locked dependency graph. Review `cargo metadata --locked` and the relevant package license files before shipping; the SDK's dual license does not automatically relicense its dependencies.

The signed test fixture `signed.jpg` was generated locally from the project's unsigned EXIF sample with c2pa-rs Builder and a disposable test-only P-256 certificate. The private key was discarded. Its test certificate is valid from 2026-11-01 to 2126-10-08 UTC, so the positive test depends on the system clock being within that range. Its SDK state is Valid with trust unknown. The test changes one byte near the end in memory and verifies the SDK reports `assertion.dataHash.mismatch`; `tampered.jpg` contains the same change for integration tests. `cawg-offline.jpg` is `ims_multiple_manifests.jpg` from the c2pa-rs 0.91.7 source distribution, under that project's MIT OR Apache-2.0 license. It has an identity reference that is unavailable offline, so the SDK reports an invalid overall state; tests preserve that diagnostic.

For distribution, use the appropriate Developer ID signing identity and notarization workflow; the build signs the nested dylib with `--timestamp=none` and does not itself perform notarization. Verify the final signed bundle on macOS.
